## 6. Outdoor Intelligence Dashboard

### Business Summary
To make product listings more relevant to buyers, the storefront includes an environmental tracker widget. The browser reads user coordinates, reverse-geocodes them into city names, and requests weather statistics. Based on these conditions, it suggests specific protective apparel (e.g. lightweight filters for high smog days or thermal fabrics for cold wind conditions).

### Technical Details
*   **OpenWeather Integration:** Fetches local temperature, humidity, and weather conditions.
*   **OpenWeather UV Index Integration:** Queries UV levels to determine local exposure values.
*   **WAQI API Integration:** Fetches localized Air Quality Index (AQI) values.
*   **Nominatim Geocoding:** Translates latitude/longitude coordinates into city and state strings.
*   **API Key Absence Fallbacks:** If API keys are missing or requests time out, the system catches exceptions and falls back to:
    *   *Weather default:* `{ temp: 30, humidity: 60, condition: 'Clear', icon: '01d', uvIndex: 5 }`
    *   *AQI default:* `{ aqi: 42, status: 'Good', color: '#009966' }`
*   **Recommendations Engine:** Uses UV, AQI, and Temperature indices to calculate a unified protection score (from Low to Extreme) and recommends clothing fabrics:
    *   *High UV (>= 6):* "High UV Today: Full facial & neck coverage advised."
    *   *Warm Temp (> 30°C):* "Warm Weather: Opt for Cool-Tech silk blend Sunwrap."
    *   *Poor AQI (> 100):* "Poor Air Quality: Use Sunwrap with integrated filtration layer."

## 7. Order Management & Transaction Pipeline

### Business Summary
The system processes purchases reliably. When a customer initiates payment, the database runs all operations—verifying product stock, reserving inventory quantities, creating the invoice record, and resetting the customer cart—as a single unit of work. If the payment fails or a product runs out of stock, the transaction is rolled back, preventing incomplete orders or duplicate charges.

### Technical Details
The order creation process uses a transactional database pipeline:

1.  **Idempotency Validation:** Validates `x-idempotency-key` in incoming request headers. If the key exists, it aborts the transaction and returns the existing order payload to prevent duplicate checkouts.
2.  **Inventory Check & Decrement:** Queries product items. If stock is available, it atomically decrements the quantity (`$inc: { stock: -quantity }`). If stock is insufficient, the transaction rolls back.
3.  **Order Generation:** Generates the database order record in `pending` status, linked to a Razorpay order ID.
4.  **Cart Clear:** Empties the user's active shopping cart.
5.  **Commit/Rollback:** Commits the transaction if all steps succeed. On any validation error, it aborts the transaction and rolls back the inventory.
6.  **Fulfillment State Machine:** Enforces valid status transitions:
    *   `pending` -> `paid` or `cancelled`
    *   `paid` -> `confirmed`, `packed`, `cancelled`, or `refunded`
    *   `confirmed` -> `packed`, `shipped`, `cancelled`, or `refunded`
    *   `packed` -> `shipped`, `cancelled`, or `refunded`
    *   `shipped` -> `delivered`, `cancelled`, or `refunded`
    *   `delivered` -> `refunded`

## 8. Authentication, Privacy & System Security

### Business Summary
The platform protects user data using modern encryption standards. Login tokens are locked inside secure browser cookies that cannot be read by external scripts, and access is monitored to prevent brute-force login attempts or bot activity.

### Terminology Definitions
*   **JWT (JSON Web Token):** A secure, encrypted digital identity card used to confirm login status.
*   **HttpOnly Cookie:** A browser cookie that blocks client-side script access, protecting session keys from theft.
*   **Bcrypt Hashing:** A cryptographic security function used to hash passwords, rendering them unreadable in the database.
*   **Rate Limiting:** Server rule setting a limit on the number of requests an IP address can make in a given timeframe to prevent server overload.

### Technical Details
*   **JWT & Cookie Authentication:** Access credentials are encrypted in JWT format and stored inside HTTP-Only, Secure, SameSite cookies. This prevents client-side scripts from reading the token.
*   **Session Management & Device Tracking:** Tracks active sessions in the database using IP hashes, device footprints, browser details, and timestamps, allowing users to audit active devices and revoke unauthorized access.
*   **Google OAuth Single Sign-In:** Google OAuth is initiated on the client using the Firebase SDK. The backend verifies the token via the Firebase Admin SDK, creating a passwordless user profile if one doesn't exist.
*   **Secure OTP Validation:** Generates a 6-digit cryptographically secure OTP, storing a SHA256 hash in a temporary table. This hash must match the user's input before registration or password recovery is complete.
*   **Brute-Force Account Locking:** Locks user accounts for 15 minutes after 5 consecutive failed login attempts, writing the block parameters directly to the user document.
*   **Strict Rate Limiting middleware:** Uses `express-rate-limit` to restrict API traffic. Login routes are limited to 20 requests per 15 minutes, and OTP requests are limited to 5 requests per 15 minutes.
*   **NoSQL Injection Cleaner Middleware:** Middleware parses all inputs and strips any parameters prefixed with `$` to protect MongoDB query parameters.
*   **XSS Cleaners & HPP Prevention:** Sanitization routines filter HTML tags from text inputs. The backend also blocks duplicate HTTP parameters (HPP) to prevent route hijack attempts.

## 9. Payment System Integration

### Business Summary
The payment system integrates directly with Razorpay, a certified payment gateway. Customer payments are verified using security signatures to prevent fraud. If a checkout is abandoned, the reserved stock is automatically returned to the store catalog after 15 minutes.

### Terminology Definitions
*   **HMAC (Hash-based Message Authentication Code):** A digital seal used to verify the integrity and authenticity of payment callback signatures.
*   **Webhook Listener:** A server script that listens for real-time transaction updates sent by Razorpay (e.g. payment confirmed).

### Technical Details
*   **Razorpay SDK Integration:** Integrates the Razorpay SDK to create payment orders. Supports fallback configurations, generating mock orders in local development environments.
*   **Secure Payment Verification:** Verifies the Razorpay payment signature by generating a local HMAC SHA256 signature using the order and payment IDs and comparing it to the signature header.
*   **Reconciling Webhooks:** Processes incoming payment events (`order.paid`, `payment.captured`). It parses signatures, matches payment records to internal orders, and updates order states to `paid` in the background if a user closes the browser during checkout.
*   **Order Stock Allocation:** Uses MongoDB transactions to handle checkouts. It checks product stock, atomically updates inventory, creates the order, and empties the cart as a single unit of work to prevent duplicate allocations.
*   **Refund Management:** The order status machine allows state updates to `refunded` and automatically restores inventory stock. However, the backend does **not** call Razorpay's API to initiate a financial refund transaction. Financial refunds must be processed manually in the Razorpay dashboard.
*   **Delayed Stock Recovery Queue:** If an order remains unpaid, a delayed job queue running via BullMQ cancels the pending order and restores the reserved product stock after 15 minutes.

## 10. Email & Automated Notifications

### Business Summary
The system sends automatic transactional emails (verification codes, welcome greetings, support receipts, invoices) without slowing down the storefront. Tasks are enqueued and processed by background workers.

### Technical Details
*   **OTP Email Flow:** Generates a 6-digit OTP during signup or password recovery, enqueuing a background email job (`enqueueEmail('registrationOTP')` or `enqueueEmail('forgotPasswordOTP')`) to deliver the validation code.
*   **Welcome Email Flow:** Upon email verification or first Google login, enqueues the `welcomeEmail` background task containing user preference tips.
*   **Contact & Support Requests:** The `/api/v1/contact` endpoint submits contact messages, sending a copy to the support desk (reply-to customer email) and an automated receipt copy to the customer. The support feedback form supports up to 5 attachments, sending them as inline attachments and cleaning up temporary disk storage once sent.
*   **Order Notifications:** Success verification triggers background PDF tax invoice and receipt generation, then enqueues the `orderConfirmation` email containing absolute links to download the files.
